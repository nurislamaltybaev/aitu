# Jarvis

Локальный десктоп-агент для Windows на Python: по горячей клавише делает скриншот, получает от vision-модели (через OpenRouter) план действий и выполняет его мышью и клавиатурой. Архитектура, поток данных и известные проблемы описаны в `HANDOVER.md`.

Клиент-серверная схема:
- **Клиент** (корень проекта, собирается в `dist\Jarvis_Portable.exe`): `main.py`, `config.py`, `screen_capture.py`, `vision_client.py` (HTTP-клиент к серверу, ключей API нет), `executor.py`, `gui.py`, `ticktick.py`, `voice.py` (голосовой ввод и озвучка).
- **Сервер** (`server/`, FastAPI, деплой по `render.yaml`): `server/main.py` (эндпоинты `/health`, `/api/plan`), `server/planner.py` (промпт, схемы `Action`/`Plan`, вызов OpenRouter, поиск Brave). Клиент импортирует из `server.planner` только схемы.

Тесты в `tests/`.

Файлы `.env` и `server/.env` могут содержать настоящий ключ API: не выводи их содержимое, не перезаписывай и не удаляй, в том числе в проверочных скриптах.

## Процесс разработки

Любую задачу на изменение кода выполняй по циклу через субагентов из `.claude/agents/`:

1. **developer** реализует задачу.
2. **critic** проверяет изменения. Если есть замечания КРИТИЧНО или ВАЖНО, **developer** исправляет их, затем **critic** проверяет снова.
3. **tester** пишет тесты и запускает весь набор, когда critic ответил «ОДОБРЕНО» или «ОДОБРЕНО С ЗАМЕЧАНИЯМИ».
4. Если тесты упали, **developer** исправляет код, затем снова **critic** и **tester**.

Один круг это проход developer → critic → tester. Максимум 3 круга. Если после 3 кругов остаются замечания КРИТИЧНО или ВАЖНО либо упавшие тесты, остановись и опиши ситуацию: что не получается, что уже пробовали, какие есть варианты.

Каждому субагенту передавай полный контекст, потому что предыдущих сообщений он не видит: developer получает задачу или полный список замечаний и падений, critic и tester получают задачу и список изменённых файлов из отчёта developer.

Замечания уровня ЖЕЛАТЕЛЬНО не запускают новый круг: перечисли их в итоговом отчёте.

В конце дай короткий отчёт:

- что сделано и какие файлы изменены;
- какие замечания дал critic и как они закрыты;
- результат тестов: сколько прошло и сколько упало.

Цикл не нужен для задач без изменения кода: вопросы, объяснения, правка документации, смена значений в `.env`.

### Команды

Запускаются из корня проекта (`C:\Users\Admin\jarvis`).

Тесты (`unittest` из стандартной библиотеки):

```
python -m unittest discover -s tests -v
```

Встроенная самопроверка планировщика, должна напечатать `ok`:

```
python server/planner.py
```

Локальный запуск сервера (ключ в `server/.env`), клиент направить на него через `JARVIS_SERVER=http://127.0.0.1:8000`:

```
python -m uvicorn server.main:app --port 8000
```

Линтер в проекте не установлен. Вместо него проверка синтаксиса и импорта:

```
python -m compileall -q -l . tests server
python -c "import main"
```

Сборка клиента (нужна, чтобы изменения попали в `dist\Jarvis_Portable.exe`):

```
build.bat
```
