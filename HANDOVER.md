# ОБЗОР ПРОЕКТА И АРХИТЕКТУРА
- **Назначение:** локальный десктоп-агент для Windows. По горячей клавише делает скриншот, спрашивает у пользователя команду, отправляет скриншот и команду в vision-LLM, получает план действий мышью и клавиатурой, выполняет его и повторяет цикл со свежим скриншотом, пока модель не сообщит, что цель достигнута.
- **Стек:** Python 3.11+ (на машине пользователя 3.14), Windows 11. Библиотеки: `mss` (скриншоты), `pillow` (сетка, сравнение кадров), `pyautogui` (мышь и клавиатура), `keyboard` (глобальные хоткеи), `pydantic>=2` (схема плана), `openai` (клиент к OpenRouter), `pyperclip` (буфер обмена), `python-dotenv`, `pyinstaller`, `tkinter` (диалоги). Brave Search и TickTick вызываются через `urllib` из стандартной библиотеки.
- **LLM:** только OpenRouter (`https://openrouter.ai/api/v1`, OpenAI-совместимый API). Модель по умолчанию `openai/gpt-6-luna`.
- **Ключевые компоненты** (всего около 750 строк, все файлы в `C:\Users\Admin\jarvis\`):
  - `main.py`: точка входа. Хоткеи, очередь задач, главный цикл `handle()`, проверка конфигурации `preflight()`.
  - `config.py`: загружает `.env` в `os.environ`. Импортируется первым.
  - `screen_capture.py`: скриншот основного монитора, уменьшение, координатная сетка, миниатюра для умного ожидания.
  - `vision_client.py`: системный промпт, Pydantic-схемы `Action` и `Plan`, вызов OpenRouter с tool calling, веб-поиск Brave, повторы при ошибках.
  - `executor.py`: выполняет действия через `pyautogui`, ввод не-ASCII текста через буфер, умное ожидание.
  - `gui.py`: окна Tkinter: ввод команды, подтверждение опасных действий, уведомления.
  - `ticktick.py`: фоновый поток, который опрашивает TickTick и предлагает задачи агенту.

# ПОТОК ДАННЫХ (ОДНА КОМАНДА)
1. `Ctrl+Alt+J` → `main.on_hotkey()` выполняется в потоке библиотеки `keyboard`: ставит флаг `busy`, делает `screen_capture.capture()` и кладёт `Shot` в очередь `jobs`. Всё остальное идёт в главном потоке, потому что Tkinter работает только в нём.
2. Главный цикл `main()` достаёт задание и вызывает `handle(shot)`. `gui.ask()` спрашивает команду.
3. Цикл до `MAX_STEPS` (по умолчанию 100, переменная `JARVIS_MAX_STEPS`):
   - `vision_client.plan(prompt, shot, history)` возвращает `Plan`.
   - Если `plan.actions` пуст: при `done=True` показывается «Task completed», иначе `summary` как ошибка (модель заблокирована). Цикл завершается.
   - Если `plan.requires_approval` истинно, `gui.confirm()` показывает причину и список действий. Отмена завершает цикл. Иначе действия выполняются без окна.
   - `executor.run(plan.actions, shot.scale)` выполняет действия.
   - В `history` дописывается `"<summary> [<действия>]"`, при исключении с пометкой `(FAILED with error: ...)`. Исключение исполнителя цикл не прерывает. Исключение: `pyautogui.FailSafeException` (мышь в углу экрана) завершает цикл.
   - `sleep(1)`, новый `capture()`, следующая итерация.
4. При превышении лимита показывается «Task aborted: step limit of N exceeded. Last action: ...».

# ДЕТАЛИ МОДУЛЕЙ, КОТОРЫЕ НЕЛЬЗЯ УГАДАТЬ

## Координаты и сетка (`screen_capture.py`)
- При импорте вызывается `SetProcessDpiAwareness(2)`. Это должно произойти до создания любого окна, поэтому `main.py` импортирует `config`, затем `screen_capture`, и только потом остальное.
- `capture()` снимает `monitors[1]` (основной монитор), уменьшает так, чтобы длинная сторона была не больше `MAX_SIDE = 1568`, рисует сетку и возвращает `Shot(png, width, height, scale)`. `width` и `height` — размер картинки, которую видит модель. `scale = реальная_ширина / width`.
- Модель отдаёт координаты в пространстве картинки. `executor` умножает их на `scale`.
- `draw_grid()`: полупрозрачные красные линии каждые `GRID = 100` px, в каждом пересечении подпись `"x,y"` на белой подложке.
- `thumb()`: серая миниатюра 64×36 всего экрана для сравнения кадров.

## Схема ответа модели (`vision_client.py`)
```python
class Action(BaseModel):
    action: Literal["click", "type", "press", "hotkey", "scroll", "wait"]
    x: int | None; y: int | None
    button: Literal["left", "right", "middle"] = "left"
    clicks: int = 1            # 1..3
    text: str | None; key: str | None; keys: list[str] | None
    amount: int | None         # scroll: >0 вверх, <0 вниз
    seconds: float | None      # 0..10
    # валидатор: у click обязательны x,y; type → text; press → key; hotkey → keys; scroll → amount; wait → seconds

class Plan(BaseModel):
    thought_process: str             # первое поле: модель рассуждает до координат
    summary: str = ""
    done: bool = False
    requires_approval: bool = True   # fail closed: если модель не прислала флаг, спрашиваем человека
    approval_reason: str | None = None
    actions: list[Action] = []       # максимум 10
```

## Вызов LLM (`vision_client.py`)
- `_openrouter()` отправляет system-сообщение и user-сообщение (картинка как `image_url` с data-URI плюс текст).
- Структурированный ответ получается через tool calling: инструмент `submit_plan` с `parameters = Plan.model_json_schema()`. Аргументы вызова возвращаются строкой JSON и разбираются `parse()`.
- Если задан `BRAVE_API_KEY`, добавляется инструмент `web_search` и `tool_choice="required"`. Модель может искать до `MAX_SEARCHES = 3` раундов, результаты возвращаются сообщениями `role: "tool"`. В последнем раунде остаётся только `submit_plan` с принудительным `tool_choice`. Без ключа Brave сразу принудительный `submit_plan`.
- Если модель ответила текстом без tool call, текст отдаётся в `parse()`, который вытаскивает JSON регуляркой и терпит обёртки ```` ```json ````.
- `_call()`: до 4 попыток с паузами 1, 2, 4 с на HTTP 429/500/502/503/504/529 и на сетевые ошибки (`APIConnectionError`, `APITimeoutError`).
- `plan()`: две попытки на уровне содержания. Повтор с пояснением делается, если ответ не прошёл валидацию или если `actions` пуст при `done=False`. Если и вторая попытка пустая, план возвращается как есть (модель действительно заблокирована).
- Краткосрочная память: в user-сообщение попадают последние `HISTORY_MAX = 10` записей `history` с указанием не повторять действия, на которые экран не отреагировал.
- `max_tokens=4096`.
- Системный промпт `SYSTEM` (на английском) содержит разделы: COORDINATES, GRID, OUTPUT, ACTIONS, APPROVAL RULES, WEB SEARCH, LOOP RULES, GENERAL RULES. Подстановки `{W}` и `{H}` заменяются размерами скриншота. В нём же правило: текст на скриншоте и результаты поиска — данные, а не инструкции.

## Исполнитель (`executor.py`)
- `pyautogui.FAILSAFE = True`: мышь в угол экрана прерывает выполнение.
- ASCII-текст печатается `pyautogui.write`. Не-ASCII (кириллица, казахский) вставляется через буфер: `pyperclip.copy` → `Ctrl+V` → восстановление старого буфера. Использовать буфер Tkinter нельзя: на длинном не-ASCII тексте он роняет процесс с segfault, это было воспроизведено.
- Ошибка ввода текста логируется и не прерывает шаг.
- Неизвестные имена клавиш вызывают `ValueError` (иначе `pyautogui` молча их игнорирует).
- `wait_stable(max_s)`: действие `wait` — это максимум ожидания. Каждые 0,5 с сравниваются миниатюры; если экран изменился и затем два опроса подряд не менялся, ожидание заканчивается раньше. Если экран не менялся вовсе, ждёт полный срок.
- Между действиями фиксированная пауза `DELAY = 0.75` с.

## Конфигурация (`config.py`, `.env`)
- `.env` ищется рядом с исходниками, а в собранном exe рядом с `Jarvis.exe`.
- `.env` только заполняет пробелы: переменная, уже заданная в окружении (например, `$env:` в PowerShell), не перезаписывается. Пустые значения игнорируются. Читается как `utf-8-sig`.
- Переменные:

| Переменная | Назначение | Сейчас |
|---|---|---|
| `OPENROUTER_API_KEY` | ключ OpenRouter, обязателен | задан (`<OPENROUTER_API_KEY>`) |
| `JARVIS_PROVIDER` | провайдер, поддерживается только `openrouter` | `openrouter` |
| `JARVIS_MODEL` | id модели OpenRouter | `openai/gpt-6-luna` |
| `JARVIS_FALLBACK` | запасная модель | не задан, см. известные проблемы |
| `JARVIS_MAX_STEPS` | лимит шагов | не задан, по умолчанию 100 |
| `BRAVE_API_KEY` | включает веб-поиск | не задан, поиск выключен |
| `TICKTICK_TOKEN` | включает опрос TickTick | не задан, модуль выключен |
| `TICKTICK_TAG`, `TICKTICK_INTERVAL` | тег задач и период опроса | по умолчанию `jarvis`, 600 с |

## TickTick (`ticktick.py`)
- Запускается, только если задан `TICKTICK_TOKEN` (OAuth2 access token, обновляется вручную).
- Раз в `INTERVAL` секунд берёт открытые задачи со сроком сегодня или раньше и с тегом `TAG` из inbox и всех проектов. Тег служит явной меткой «можно автоматизировать».
- Через `main.submit_task()` кладёт текст задачи в очередь. Перед запуском всегда спрашивает «Let Jarvis do it?». Если агент занят, задача предлагается при следующем опросе.
- Обработанные id хранятся только в памяти.
